## Layout settings, and what to touch if something still overflows

A 10pt two-column A4 page with 1.9 cm margins leaves each column **8.2 cm** wide, which is narrow.
Four things in the preamble exist specifically to keep content inside it:

- `\setlength{\tabcolsep}{4pt}` (LaTeX default is 6pt). With five or six columns the default padding
  alone costs over a centimetre.
- All five tables are `\footnotesize`, not `\small`. At `\small` the cleaning ledger and the headline
  results table both run past the column edge.
- `\usepackage[htt]{hyphenat}` lets `\texttt{...}` hyphenate. Without it a long identifier such as
  `pretrained_resnet18_train.ipynb` cannot break, so TeX stretches the inter-word spaces on that
  line instead, which is what produced the uneven gaps. If Overleaf ever errors on this package,
  deleting the line is safe: the `\allowbreak` markers inside the long paths do most of the same job.
- `\newcommand{\class}[1]{\textsf{#1}}` deliberately does **not** set a font size. An earlier version
  forced `\small`, which made class names smaller than the body text and *larger* than the
  surrounding text inside a `\footnotesize` table.

Widest cell in each table, against the 8.2 cm budget: Table 1 about 6.3 cm, Table 2 about 5.8 cm,
Table 3 about 6.2 cm, Table 4 about 5.3 cm, Table 5 about 6.3 cm. If you add a column or lengthen a
row label, check it against that budget. Should a table still overflow, the fixes in order of
preference are: shorten the longest row label, then `\scriptsize`, then promote it to `table*` so it
spans both columns (which costs vertical space, so it is a last resort).

## What changed against `main (1).tex`

The earlier draft was written from an older training run. Its model numbers do not match anything
currently in `results/`, so every one of them was replaced. The data and cleaning sections were also
re-checked against the local full-dataset run in `results/01_eda/` and `results/02_data_split/`.

**Model results, all replaced.** The draft's numbers are on the left, the committed run in
`results/model_comparison.csv` (which agrees with `docs/experiment_results.md`) on the right.

|---|---|---|

| pretrained `test_ood` acc / F1 / AUC | 0.766 / 0.430 / 0.802 | 0.774 / 0.429 / 0.814 |
| scratch `test_id` acc / F1 / AUC | 0.791 / 0.648 / 0.914 | 0.768 / 0.615 / 0.903 |
| scratch `test_ood` acc / F1 / AUC | 0.687 / 0.381 / 0.805 | 0.630 / 0.377 / 0.790 |

| scratch epochs / best / time | 40 / 32 / 37.7 min | 16 / 8 / 14.2 min |
| GPU | RTX 5060 | RTX 4070 |

Two conclusions flipped as a result:

- The draft said the from-scratch model had a **higher ROC-AUC on all three splits**. It does not.
  In the current run the pretrained model wins on every split and every metric.
- The draft reported the pretrained model's out-of-domain error direction as 74.4% over-estimate and
  a 20.7% false-alarm rate. Those came from a confusion matrix that was never exported to
  `results/`, so they are not verifiable and were removed. The report now gives the 19.5% false-alarm
  rate (which follows exactly from `no-damage` recall 0.805) and quotes the measured 81.1% / 18.9%
  error split for the from-scratch model, whose confusion matrices are in `results/`.

Everything else in Part 1 reproduced exactly: 11,034 scenes, 425,368 polygons, the per-split scene

**Part 3 is new and was re-run.** The committed `results/socio_analysis/regression_results.csv` is
not usable as it stands:

- The ACS extract encodes missing values as the Census sentinel `-666666666` rather than as nulls,
  and 17 of the 308 block groups carry one. They were never filtered, which is why
  `median_building_age` has a maximum of 666,668,700 years.
- `pov_rate_2017` is empty for all 308 rows, yet appears in the output with a coefficient of
  1.39e-17 and p = 0.0. That is a rank-deficiency artifact of the pseudo-inverse fallback, not a
  finding.
- `exposure_proxy` is identically 0.0 for every row (`data/hazard_exposure.csv` was never
  populated), so the "controlled" model in that file controls for nothing.

The report uses a re-run on the 291 clean block groups, with the two dead columns dropped and event
fixed effects added as the exposure control. Naive R2 goes from 0.016 to 0.045 and the strongest
specification reaches 0.225. The headline: median income looks significant
(+0.225, p = 0.0009) until event fixed effects enter, at which point it is +0.057, p = 0.44.

## Known gaps, stated in the report

- `checkpoints/pretrained.pt` and `checkpoints/scratch.pt` do **not** correspond to the run in
  `results/`. Their architectures differ (the pretrained head has no BatchNorm layer, 11,571,012
  parameters against the reported 11,571,524; the scratch encoder emits a 128-d embedding against
  the reported 256-d). They are leftovers from earlier experiments and cannot be used to reproduce
  or extend the reported numbers.
- `results/pretrained_resnet18/` has no `confusion_matrices.csv`. The training notebook writes one
  to `work-pretrained/`, which is gitignored and absent. Re-running that notebook would let the
  pretrained confusion matrix be plotted next to the from-scratch one.
